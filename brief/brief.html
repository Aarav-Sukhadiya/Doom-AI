Doom-AI: an agent that plays DOOM levels it has never seen

Yugaantar 2026, DevForge, Track 1 "Can It Play DOOM?"  |  github.com/Aarav-Sukhadiya/Doom-AI  |  entry point submission/agent.py

1. The problem and our idea

The organisers test agents on unseen maps in four tiers: combat and survival, multi-room exploration with doors, long keycard routes, and a full gauntlet with several locks. An agent that memorises button sequences or a single map fails on new layouts. It has to learn general skills: fight, explore, find keys, remember where the matching door was, and get back to it.

Our USP: the agent remembers places, not button sequences. It builds three memories while it plays, all from what any player can observe: landmarks (where it last saw a key, a locked door, a door, health, ammo, armour or a weapon), breadcrumbs (how often it has walked each patch of ground) and a map it draws itself from its 64 distance sensors. The game never gives it coordinates; it tracks its own position by dead reckoning from its turns and velocity, like counting steps in the dark. A trained neural network reads these memories and makes every decision.

2. System architecture

Each decision covers 4 game tics. The whole network decides in about 6 ms on one CPU thread (the limit is 40 ms), uses 1.6 GB of RAM and 290 MB of GPU memory (limits 8 GB and 2 GB), and loads only from submission/. Each new memory was added as a residual branch whose output starts at zero, so a trained agent could be extended without forgetting what it already knew.

3. Technical approach

Learning

Recurrent PPO with GAE, trained from scratch on one laptop (RTX 5070 Laptop GPU, 16 threads): 56 games in parallel in lightweight worker processes, about 2,000 decisions per second, about 95 million decisions in total. Gradients flow through the GRU over 32-step chunks.

Practice levels

Our level generator writes real DOOM maps from text layouts in the four tiers and proves each one solvable before use. Seeds are split 80/10/10 into practice, validation and locked test levels. The agent also practises on 56 real Freedoom maps; 12 more are kept back only for testing. Difficulty rises per tier as the agent improves, and a controller shifts practice between tiers from test results.

Rewards (training only)

The exit is worth the most (25, plus health and time bonuses). Smaller rewards go to keys, doors, locked doors, new areas and ground, kills, pickups and dodging incoming fireballs. Damage, dying early, wasted ammo and pressing USE on a door it has no key for all cost points. A training-only hint rewards progress toward the next key, its door, then the exit. None of this reaches the submitted agent.

Testing and safe shipping

Every 200 updates a snapshot plays 80 validation levels and our copy of the official test: 25 locked levels per tier with the official time and compute limits, scored in the four official categories. It ships only if both tests agree it is better and validate.py passes.

5. What we learned

  • Measure before changing. Watching recorded runs found most of our fixes: the agent could not change weapons (no action produced the button), sprayed ammo at nothing, pressed USE 27 times on a yellow door without the key, and walked away from an exit 2 tiles away because nothing it senses shows the exit.
  • Rewards shape behaviour more than architecture. Raising the exit reward from 10 to 25 gave the largest single gain. Penalties for standing still in fights made the policy steadily more random and the score fell, so we removed them and used positive rewards for dodging instead.
  • One test is not enough. Validation and our official-style test once disagreed for 400 updates; a larger test showed keycard skill slipping after we cut its practice share. Shipping now needs both.
  • Known limits. Several enemies at once, exits far from everything else, and very large real maps. More practice time on tier 4 and real maps is the clearest next step.

6. Playing by the rules

  • Every action comes from the trained network. There is no path-finding, no auto-aim and no hand-written behaviour. The only fixed logic is two masks taken from observation fields (no firing without an enemy in view, a USE cooldown so a moving door is not reversed), which the rules allow.
  • During evaluation the agent sees only the official observations through the organisers' unmodified doom_env. Privileged game state is used only to compute training rewards.
  • All code was written during the hackathon. Weights are in Git LFS; env/, docs/, tests/ and validate.py match the latest template; the training code is in training/ with a guide in training/README.md.
